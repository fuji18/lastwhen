# 要求: 一覧の並びを相対経過度の降順にする(Issue #23 / F30)

## 背景・目的

古びているものが上に来る一覧にする。**順序を決めるのは経過日数ではなく相対経過度**(#20)。
「車の点検 180日前(基準 180 日)」より「風呂掃除 14日前(基準 7 日)」が上に来る。
#21(経年変化の見た目)と同じ原理を並び順にも通す。

## 並び順の規則

1. 相対経過度の**降順**(大きいほど上)
2. 相対経過度が `null`(記録 1 件以下・未実施)の項目は**下部にまとめ、登録順**
3. 同値は登録順(`sortOrder`)で安定させる

## 必須要件: 記録した瞬間にカードが飛ばないこと

並び順は**一覧を表示した時点で確定させ、記録操作では組み替えない**。組み替えは次に一覧を開いたとき
(またはアプリが前面に復帰したとき)に反映する。押したカードはその場で `今日` になり、位置は動かない。

## スコープ

- 並び替えの純関数とユニットテスト
- `ItemListNotifier` での適用と、並び順を固定するタイミングの制御
- 一覧のウィジェットテスト(並び順・記録後に動かないこと・復帰で反映)
- PRD に F30 を追加 / 機能設計「UI設計」に並び順の規則を追記

## スコープ外

- 並び替えを選ぶ UI(F15 本体)/ カテゴリ別の並び(F13)/ 経年描画(#21)/ 詳細シート(#22)

## 受け入れ条件

- [ ] 一覧が相対経過度の降順で並ぶ
- [ ] 基準 7 日・14 日前の項目が、基準 180 日・180 日前の項目より上に来る(ウィジェットテスト)
- [ ] 相対経過度 `null` の項目が下部にまとまり、その中では登録順
- [ ] 同値の項目の順序が安定している(再描画で入れ替わらない)
- [ ] 「やった」を押してもそのカードの位置が動かない
- [ ] 一覧を開き直す(または復帰する)と新しい並びが反映される
- [ ] 並び替えは `List<ItemView>` 生成時の 1 回で済み、`ListView.builder` のビルド中に走らない
- [ ] 100 件で並び替えを含めた変換が 300ms 以内
- [ ] ユニットテスト(降順 / null の下部固定 / 同値の安定性 / 空リスト)
- [ ] `dart format` / `flutter analyze --fatal-infos` / `flutter test` が通る
