# 要求: 基準間隔にもとづく通知(F11)と F9 / F10 の取り下げ(Issue #51)

## 背景

アプリを開かないと経過に気づけない。PRD の F11(通知)は F9(目安期間の手動設定)が前提だったが、
F27(基準間隔の学習)で**設定を求めずに**「いつもより間が空いた」を判定できるようになった。
基準間隔を使う形で F11 を実現し、F9 / F10 を取り下げる。

## スコープ

- 相対経過度が「経過」(1.5 以上)に入った項目について、ローカル通知を 1 回だけ出す
- 通知の予約を OS に張る仕組み(計画 = `domain/`、予約 = `data/`、追従 = `state/`)
- 通知権限の要求(通知する項目が初めて生じた時点)と、拒否時の振る舞い(他機能は動く)
- 通知のオフは OS の通知設定に任せる(アプリ内に設定を持たない)
- docs の更新(PRD の F9 / F10 取り下げと F11 の前提、architecture / functional-design / repository-structure)

## スコープ外

- F9 / F10、サーバーからのプッシュ通知、通知からの記録(通知アクション)
- 配信済みの通知を通知センターから消すこと
- `integration_test` の導入(導入しないと決めた。`docs/architecture.md`)

## 受け入れ条件(Issue #51 より)

- [ ] 基準間隔のある項目が「いつもより間が空いた」状態に入ったとき、1 項目につき 1 回だけ控えめな通知が届く
- [ ] 基準間隔が無い項目(記録 1 件以下・未実施)では通知しない
- [ ] 記録・編集・削除で、その項目の予定済み通知が更新/取り消される
- [ ] 通知権限は、通知が必要になった時点で要求する(初回起動で要求しない)。拒否されてもアプリの他機能は動く
- [ ] 通知をオフにする手段がある(OS の通知設定)
- [ ] Android 8.0 以上 / iOS 15 以上で動く(iOS 実機確認は macOS 側)
- [ ] PRD から F9 / F10 が取り下げとして明記され、F11 の前提が F27 に書き換わっている
- [ ] スケジューリング判定のユニットテストがある
- [ ] `dart format` / `flutter analyze --fatal-infos` / `flutter test` が通る

## ユーザー確認済みの判断(2026-09-27)

- しきい値 = 相対経過度 1.5(`aged`)
- 通知時刻 = しきい値に達した暦日のローカル 19:00
- オフの手段 = OS の通知設定に任せる
