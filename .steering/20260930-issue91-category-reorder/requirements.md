# 要求内容

## 概要

設定のカテゴリの管理で、カテゴリをドラッグして並び替えられるようにする(F13 / Issue #91)。並びは `categories.sort_order` に保存し、カテゴリを並べる各所(一覧のチップ・図鑑の絞り込み・項目の追加/編集のカテゴリ選択・バックアップ)に同じ順で反映する。

## 背景

実機確認(#90)で出た要望。カテゴリの表示順は作った順(`sort_order` = `MAX + 1`)で固定されていて、よく使うカテゴリを前に出せない。

## 実装対象の機能

### 1. 並び替えの保存
- リポジトリに並び替えの操作を足し、全カテゴリの `sort_order` を 0 始まりで振り直す。**1 トランザクション**で行う

### 2. 管理画面のドラッグ操作
- `ReorderableListView` でドラッグハンドルからドラッグして並び替える
- 保存の完了を待ってから表示を変える(楽観的 UI 更新を採らない)
- 読み上げでも並び替えられる(`ReorderableListView` 組み込みのカスタム操作「上に移動」など)

### 3. docs の更新
- PRD F13 行、functional-design のカテゴリ節・CategoryRepository 節・カテゴリの絞り込み節、glossary のカテゴリ行

## 受け入れ条件

- [ ] カテゴリの管理でカテゴリをドラッグして並び替えられる
- [ ] 並び替え後、一覧のチップ・図鑑の絞り込み・追加/編集のカテゴリ選択が同じ順で並ぶ
- [ ] アプリを再起動しても並びが保たれる
- [ ] 書き出し → 復元で並びが保たれる
- [ ] 新しく追加したカテゴリは末尾に入る
- [ ] 並び替えの途中で失敗しても `sort_order` が中途半端な状態で残らない(トランザクションのテスト)
- [ ] 読み上げで並び替えられる(docs/ui-design-guidelines.md §6)
- [ ] PRD F13 行・functional-design のカテゴリ節が更新されている
- [ ] リポジトリのテストとウィジェットテストがある

## スコープ外

- スキーマ変更・マイグレーション(`lib/data/database/` / `lib/data/migrations/` に触れない)
- 項目の手動並び替え(F15 / F30 の範囲)
- 並び替えの取り消し導線
