# 要求: 項目の新規登録(Issue #6)

> 出典: GitHub Issue #6 / `docs/product-requirements.md` F2 / `docs/functional-design.md`「UC2: 項目を登録する」
> 依存: #5(一覧画面)—— クローズ済み(PR #25)

## 背景

#5 で一覧画面と空状態までができたが、**項目を作る手段がまだ無い**。
`ItemListScreen._handleAddPressed` も `EmptyState` の導線も空実装のまま置いてある。
このチケットで実際に登録できるようにし、アプリが単体で使える状態にする。

成功指標「管理項目を 30 秒以内に登録できる」「初回利用時に 3 件以上登録するユーザー 50%」に
直結するため、**入力項目を増やさないこと自体が設計要件**になる。項目名 1 つだけで登録が完了する。

## スコープ(やること)

- `lib/ui/screens/item_add_screen.dart`: 登録画面(項目名 1 項目のみ)
- 一覧画面から登録画面への導線(追加ボタン)と、空状態の既存導線の結線
- `ItemListNotifier.addItem`: 検証 → 保存 → 結果を結果型で返す
- 保存の結果型(`lib/state/add_item_result.dart`)
- 登録後に一覧へ戻り、追加された項目が `未実施` で見える
- ユニットテスト(state)とウィジェットテスト(UI)
- `test/support/fake_item_repository.dart` に書き込み失敗の注入口を足す(#7 / #8 でも使う)

## スコープ外(やらないこと)

- カテゴリ・アイコン・目安期間の入力(P1。#20 以降)
- テンプレート項目のワンタップ追加(P2)
- 登録と同時に最終実施日を入力する(**登録直後は必ず未実施**)
- 「やった」の記録・取り消し(#7)/ 編集・削除(#8)
- 名前付きルートの導入(判断4)
- `writeErrorProvider` の新設(判断2。#7 の担当)

## 受け入れ条件(Issue #6 より)

- [ ] 一覧画面から **1 タップ**で登録画面に到達できる
- [ ] 空状態の導線からも登録画面に到達できる
- [ ] **項目名のみの入力で登録が完了する**(他の入力を必須にしない)
- [ ] 項目名が空、または空白のみの場合は登録できず、理由が表示される
- [ ] エラー時に画面が閉じず、入力内容が保持される
- [ ] 項目名は 51 文字以上を入力できない
- [ ] 前後の空白がトリムされて保存される
- [ ] 登録直後の項目は `未実施` として一覧に並ぶ(経過日数も日付も出ない)
- [ ] 登録画面を開いた時点で入力欄にフォーカスが当たり、キーボードが出る
- [ ] キャンセルすると何も保存されずに一覧へ戻る
- [ ] **保存に失敗した場合、一覧を更新せず**に失敗が伝わる
- [ ] 登録開始から完了まで 30 秒以内に行える動線になっている
- [ ] `flutter analyze --fatal-infos` と `flutter test` が通る

## 制約

- **楽観的 UI 更新を採らない**(`CLAUDE.md`「譲らない設計判断」)。保存の成功を待ってから一覧へ戻る
- 長さ・空の判定は `lib/domain/item_name.dart` の `validateItemName` が唯一の権威。**画面側で書き直さない**
- 検証の失敗は例外ではなく結果型で返す(`docs/development-guidelines.md`「エラーハンドリング」)
- 用語は「項目」「登録」。「タスク」「アイテム」と書かない(`docs/glossary.md`)
- 追加の UI パッケージを入れない。Material 3 の組み合わせで作る(`CLAUDE.md`)
- 色・余白・タイポは `Theme.of(context)` 経由で取る
- `pubspec.yaml` に依存を足す必要が出たら、実装を止めて司令塔に戻す
