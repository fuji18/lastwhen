# 要求: 下部ナビの「設定」と設定画面(Issue #81)

## 背景

実機確認(#65)で、カテゴリの管理が一覧の AppBar のボタンにしか無く見つけにくいと分かった。
また公開するアプリには、注意事項・プライバシーポリシー・バージョン・OSS ライセンスを
アプリ内で確認できる場所が要る。下部ナビに「設定」を足し、1 画面にまとめる(旧 #71 を統合)。

## やること

- 下部ナビを **ホーム / 図鑑 / 設定** の 3 つにする。起動直後は必ずホーム、タブ切替で取り消し導線を閉じる、は現状どおり
- 設定画面を新設する: カテゴリの管理への入口 / 注意事項 / プライバシーポリシーへの導線 / このアプリについて(バージョン・ライセンス)
- 項目の追加の FAB は変えない

## やらないこと

- 保存される設定値を持つこと(「設定を求めない」方針は変えない。中身は入口と情報の表示だけ)
- 項目の追加ボタンの移設 / バックアップ(#68)/ 利用規約

## 計画時の決定(司令塔)

| # | 論点 | 決定 | 理由 |
| --- | --- | --- | --- |
| 1 | 一覧 AppBar のカテゴリ管理ボタン | **外す**。入口は設定の 1 つに絞る | 見つけにくさの解消が目的で、入口が 2 つあると「どちらが正か」がぶれる。未公開なので既存ユーザーの学習コストは無い。AppBar の混雑(判断H)も減る |
| 2 | バージョンの取得 | **Dart の定数**(`lib/ui/app_info.dart`)に持ち、`pubspec.yaml` の `version` と一致することを**テストで照合**する。`package_info_plus` は入れない | 新規依存とプラットフォームチャネルを増やさない。取り違えは CI で落ちる。バージョンを上げるのはリリース用 PR だけ(development-guidelines「バージョンの運用」)なので、同じ PR で定数も直せば足りる |
| 3 | プライバシーポリシーの URL | **表示とコピー**に留める。`url_launcher` は入れない | ポリシー本文が「本アプリにはインターネットに接続する機能がありません」と書いている。ブラウザ起動の導線も置かない方が本文と素直に揃う。新規依存も増えない |
| 4 | 設定タブの `ScaffoldMessenger` | 図鑑と同じく**専用の `ScaffoldMessenger` で包む**。さらにタブ切替時にその中の `SnackBar` も閉じる | 包まないと一覧の取り消し導線が設定にも複製され、Hero タグが衝突する(#34 判断9)。設定側はコピー完了の `SnackBar` を出すため、切替時に閉じないと戻ったときに古い通知が残る |

新規依存が無く、委託禁止領域(`lib/data/database/` / `lib/data/migrations/`)にも触れないため、実装は Codex に委託できる。
