# 要求: 実施履歴の保持と基準間隔の学習(Issue #20)

## 目的

「やった」のたびに実施日を履歴(`done_logs`)として残し、履歴から項目ごとの**基準間隔**
(その項目のだいたいの周期)を学習する。#21(経年変化)・#22(詳細画面)・#23(並び順)の
共通の前提になる。**ユーザーに間隔を設定させない。**

要求の全文と受け入れ条件は Issue #20 の本文とコメント(2026-09-23 の画面イメージを受けた決定)が正。

## このチケットでやること

- `done_logs` テーブルの追加と `schemaVersion` 2 へのマイグレーション(既存の最終実施日を 1 行ずつ移送)
- 記録・取り消しで `items` と `done_logs` を同一トランザクションで書く
- 一覧取得に項目ごとの直近履歴を載せる(N+1 にしない)
- 前回間隔 / 基準間隔 / 相対経過度の算出(ドメインの純関数)と、表示モデル(`ItemView`)への搭載
- マイグレーションテスト・ユニットテスト
- ドキュメント追記(PRD F27 / 機能設計の ER 図 / 用語集)

## やらないこと

- 経年変化の描画(#21)・詳細画面(#22)・並び順(#23)。**UI は一切変えない**
- 目安期間の手動設定(F9)・通知(F11)・履歴の編集削除・統計表示
- 古い履歴の剪定

## 画面イメージを受けた決定(Issue #20 コメント)

- 算出の定義は Issue 本文のまま(直近最大 5 間隔の中央値、記録 1 件以下は `null`)
- 画面上の呼び名は「平均」。コード・ドキュメントの用語は「基準間隔」のまま。用語集にその旨と「計算は中央値」を注記する
- 基準間隔が `null` の項目は画面上「学習中」と表示する(表示の実装は #21 / #22。このチケットでは用語集に書くだけ)
