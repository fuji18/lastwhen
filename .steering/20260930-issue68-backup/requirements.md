# 要求内容

## 概要

全データ(項目・記録の履歴・カテゴリ・アイコン)を 1 つのファイルに書き出して OS の共有シートで端末の外へ渡し、そのファイルから復元できるようにする(F26 / Issue #68)。入口は設定画面(#81)に置く。

## 背景

端末の移行手段が OS の自動バックアップしかない(`docs/architecture.md`「バックアップ戦略」)。自動バックアップが無効な端末や、OS をまたぐ移行では記録がすべて失われる。記録の信頼性が製品価値そのものなので、公開前に、ユーザーが自分で書き出して復元できる経路を用意する。

## 実装対象の機能

### 1. データの書き出し
- 設定画面の「データを書き出す」で、全データを JSON ファイル 1 つにまとめ、OS の共有シートを開く
- ユーザーは共有先(Google ドライブ・メール・ファイルなど)を自分で選ぶ。アプリは自動で送信しない

### 2. データの復元
- 設定画面の「データを復元する」で、OS のファイル選択を開き、書き出したファイルを選ぶ
- ファイルを検証し、問題があれば理由を表示して**何も変えない**
- 問題がなければ件数を示して確認を取り、**全置換**で復元する(元に戻せないため確認を入れる)
- 復元後は一覧・図鑑・カテゴリ・通知の予約が復元後のデータで作り直される

### 3. docs の更新
- PRD の F26 を P2 → P1 に移し、「スコープ外」からエクスポートを外す
- architecture の「バックアップ戦略」・依存表、functional-design の設定・ファイル構造・セキュリティ・エラー、glossary の用語を更新する

## 受け入れ条件

### 書き出しと復元
- [ ] 書き出し → アプリを入れ直す → 復元、で項目・記録の履歴・カテゴリ・アイコンが元どおりになる。`lastDoneAt` が `done_logs` の `MAX(done_at)` と一致している
- [ ] 復元は既存データを上書きするので**確認を入れる**
- [ ] 形式が不正・バージョン不一致・壊れたファイルでは、既存データを**一切変えずに**理由を表示する(1 トランザクションで入れ替える)
- [ ] ファイルに形式のバージョンを持たせ、日時は UTC のまま保存する
- [ ] 復元の後、通知(F11)の予約が復元後のデータで取り直される
- [ ] ストレージ権限・`INTERNET` 権限を追加しない(release のマージ済みマニフェストで確認)

### テスト
- [ ] ユニットテスト(インメモリ DB での往復、不正なファイルで既存データが残る)がある

### docs
- [ ] PRD / architecture / functional-design / glossary が更新されている

## 成功指標

- 機種変更・OS 変更でも、ユーザー自身の操作だけで記録を引き継げる

## スコープ外

- クラウドへの自動バックアップ・同期(F19)
- 自動の定期書き出し
- 他アプリ形式(CSV など)の読み込み
- 既存データとのマージ(復元は全置換のみ)
- ファイルの暗号化・パスワード保護
- iOS 実機での動作確認(devcontainer では iOS ビルドができない。iOS 公開チケット #75 / #76 で扱う)
