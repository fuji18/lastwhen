# 要求内容: カテゴリと絞り込み(Issue #33 / F13)

## 概要

項目にカテゴリを 1 つ持たせ(任意)、一覧の上部に並べたチップで絞り込めるようにする。
カテゴリは初期値 4 つ(生活 / 健康 / 趣味 / その他)から始まり、ユーザーが追加・名前変更・削除できる。

## 背景

画面イメージ(`docs/ideas/LastWhen_gamen.png`)の図鑑画面に「すべて / 生活 / 健康 / 趣味 / その他」の絞り込みチップがある。
PRD F13 は P1。P0 はすべてクローズ済みで、MVP 完了後の P1 として着手する(前倒しではない)。依存先の #32 はクローズ済み。

## Issue の未決事項に対するユーザーの決定(2026-09-24)

| 未決事項 | 決定 |
| --- | --- |
| カテゴリの区分(PRD と画像の食い違い) | **画像に合わせる**: 生活 / 健康 / 趣味 / その他。PRD F13 を更新する |
| 固定か、ユーザーが追加できるか | **ユーザーが追加できる**(名前変更・削除もできる) |
| 絞り込みの置き場所 | **ホームの一覧に置く**。図鑑(#34)ができたら同じウィジェットを使い回す |

## 実装対象の機能

### 1. カテゴリの保存
- `categories` テーブルを足し、`items` に `category_id` 列(NULL 許容)を足す。スキーマ v4 のマイグレーション
- **NULL = 未分類**。カテゴリは任意で、選ばなくても登録できる(PRD F2 を守る)
- 新規インストール・既存ユーザーの移行のどちらでも、初期カテゴリ 4 つを用意する
- 既存の項目は移行後に未分類。記録・履歴は一切変わらない

### 2. カテゴリの管理
- 一覧の AppBar から「カテゴリを管理」画面を開く。追加・名前変更・削除ができる
- 登録・編集画面のカテゴリ選択欄からも追加できる(追加したカテゴリがそのまま選ばれる)
- カテゴリ名はトリム後 1〜10 文字、重複不可
- **削除は確認を挟む**(割り当ては元に戻せないため)。そのカテゴリの項目は未分類になり、**項目と記録は消えない**

### 3. 絞り込み
- 一覧の上部にチップを横に並べる:「すべて」+ カテゴリ(表示順)。単一選択
- 選んだカテゴリの項目だけを出す。「すべて」は未分類を含む全項目
- 絞り込み中に「項目を追加」すると、登録画面でそのカテゴリが選ばれた状態で開く

## 受け入れ条件

### 保存
- [ ] v3 → v4 のマイグレーションで既存の項目・履歴が 1 件も失われず、`category_id` は NULL になる。初期カテゴリ 4 つがこの順で入る
- [ ] 新規作成した DB にも初期カテゴリ 4 つがこの順で入る
- [ ] カテゴリを選んで登録・編集すると、再読込後も同じカテゴリで出る
- [ ] カテゴリを削除すると、その項目は未分類になり、最終実施日・履歴は変わらない

### 管理
- [ ] 追加・名前変更・削除ができ、一覧のチップと選択欄にすぐ反映される
- [ ] 空・11 文字以上・既存と同じ名前は保存されず、ダイアログに理由が出る
- [ ] 削除は確認ダイアログで「削除」を押したときだけ実行される

### 絞り込み
- [ ] 「すべて」とカテゴリのチップが出る。カテゴリが 0 件ならチップ列を出さない
- [ ] カテゴリを選ぶとその項目だけが出る。該当が 0 件なら「このカテゴリの項目はありません」と出る
- [ ] 選択中のカテゴリが削除されたら「すべて」に戻る
- [ ] 絞り込んでも並び順(F30)は変わらない(絞り込み前の並びの部分列になる)
- [ ] チップは 48dp 以上のタップ領域を持ち、読み上げで選択状態が分かる

## 成功指標

- 登録の 30 秒要件(PRD)を崩さない: カテゴリ選択は任意で、入力欄の自動フォーカスを維持する

## スコープ外

- カテゴリの並び替え(追加順で固定)
- 絞り込み状態の保存(アプリを再起動すると「すべて」に戻る)
- カテゴリからの既定アイコン、カードや詳細シートへのカテゴリ表示
- 図鑑画面・下部ナビ(#34)
- 「未分類」だけを出す絞り込み
