# 要求: プライバシーポリシーとデータセーフティの申告(Issue #70)

## 背景

Google Play は**プライバシーポリシーの URL** と**データセーフティの回答**がないと審査に出せない。データを 1 件も収集しないアプリでも両方が要る(Play Console ヘルプ「データ セーフティ セクション」)。アプリ内への掲示(#81 の「このアプリについて」)は URL に**加えて**要るもので、URL の代わりにはならない。

## ユーザーの決定(2026-09-29)

| 論点 | 決定 | 理由 |
| --- | --- | --- |
| 公開先 | **GitHub Pages に Actions でデプロイする**。公開するのは `site/` だけ | リポジトリは public。`/docs` をそのまま配信すると設計ドキュメントまでサイトになる。GitHub のファイル表示 URL ではリポジトリの画面ごと表示され、ポリシーのページとして弱い |
| 問い合わせ先 | **「各ストアの掲載ページに記載のデベロッパー連絡先」+ GitHub Issues** を併記する。メールアドレスはリポジトリに書かない | Play はストアページにデベロッパーのメールを必ず公開表示するので、メールを二重に管理しなくて済む。#83(メールの決定)を待たずに公開できる。#69 R4「メールはリポジトリに書かない」と矛盾しない |

## 司令塔の決定

| 論点 | 決定 | 理由 |
| --- | --- | --- |
| ページの形式 | **手書きの静的 HTML 1 枚**(`site/privacy-policy/index.html`)。Jekyll などのビルドを挟まない | ページは 1 枚だけ。ビルドを挟むとテーマ・Ruby の依存が増える(architecture「供給網」)。ワークフローは成果物のアップロードとデプロイだけで済む |
| URL | `https://fuji18.github.io/lastwhen/privacy-policy/` | 後からページを足しても URL が変わらないよう、ルートではなくサブパスに置く |
| デプロイの契機 | `main` への push で `site/**` か当のワークフローが変わったとき + 手動実行 | ポリシーの改定がそのまま公開に反映される。無関係な push でデプロイしない |
| 提供者の表記 | 「本アプリの開発者」とし、組織名は書かない | 組織名は Play Console の登録(#83)で決まり、ストアページに表示される。ポリシーと二重に管理しない |
| データセーフティ | **「収集なし・共有なし」** | release のマージ済みマニフェストに `INTERNET` が無い(`POST_NOTIFICATIONS` / `RECEIVE_BOOT_COMPLETED` / `VIBRATE` と、プラグインが定義する内部用の権限だけ)。解析・広告・クラッシュ収集の SDK も無い |
| OS の自動バックアップ | データセーフティの「収集」に**当たらない**と判断する。ポリシーには明記する | Google の定義は「アプリが端末から送信すること」。自動バックアップは OS が行い、開発者はそのデータを読めない。ヘルプはこれについて明記していないので、判断の根拠を回答案に残す |
| 書き出し(F26 / #68) | まだ実装していないが、ポリシーには「書き出した場合」の形で書いておく | #68 は公開前に入る P1。ユーザーが自分で共有先を選ぶ送信は、Google の定義で「共有」の申告の対象外 |
| 制定日 | 2026年9月29日 | — |

## 要求

| # | 要求 | 出典 |
| --- | --- | --- |
| R1 | ポリシー本文(日本語)に次がすべて入っている: 収集・送信しない / 端末内に保存する / OS の自動バックアップによる複製 / 通知の権限の用途 / 書き出したファイルはユーザーの操作でのみ端末の外へ出る / 第三者提供なし / 問い合わせ先 / 制定日・改定日 | 受け入れ条件 2 |
| R2 | プラットフォーム固有の書き方を避ける(Android と iOS の両方で使い回せる) | スコープ |
| R3 | 内容が architecture「セキュリティ制約」と矛盾しない | 受け入れ条件 2 |
| R4 | GitHub Pages のワークフローで `site/` を公開し、ログインなしで URL にアクセスできる | 受け入れ条件 1 |
| R5 | データセーフティの回答案と、根拠(権限・依存)の確認手順がリポジトリにある | 受け入れ条件 3 |
| R6 | PRD「未決事項」#5 を決定に移す | 受け入れ条件 4 |
| R7 | `site/` と回答案の置き場所を repository-structure に書く | 受け入れ条件 5 |

- アプリ内からポリシーへの導線(#81)
- 利用規約
- Play Console への入力そのもの(#73。人手の作業)
