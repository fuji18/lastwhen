# 要求内容: アクセシビリティとパフォーマンスの仕上げ(Issue #9)

<!-- status: ready -->

## 概要

P0 の機能要件(#2〜#8)が揃った状態で、**画面をまたいだ非機能要件を機械的に確認して埋める**。
新機能は 1 つも足さない。MVP を「出せる」状態にする最後のチケット。

## 背景

機能チケットの受け入れ条件には個別のアクセシビリティ項目が入っているが、
**画面をまたいだ一貫性は揃ってからでないと確認できない**。計画時に一覧・登録・編集の
3 画面を実測したところ、以下が判明した(2026-09-20 / `flutter test` / 360×640dp)。

| 実測項目 | 結果 |
| --- | --- |
| コントラスト比(light / dark の使用ペア全て) | **6.14:1 以上。AA を既に充足**(修正不要) |
| 文字サイズ 100% の一覧 | **`431日前` が幅 91.9px で省略されている**(製品の中心要素が切れている) |
| 文字サイズ 150% / 200% の一覧 | 項目名・最終実施日・経過日数がすべて省略される |
| 文字サイズ 200% の登録・編集画面 | 省略もオーバーフローも無し(現状維持でよい) |
| 「やった」ボタンの実寸 | 100% / 150% / 200% のいずれでも高さ 56dp を維持 |
| `Semantics` の使用箇所 | **0 箇所**。行内の「やった」ボタンは項目名なしで読み上げられる |

つまり埋めるべき穴は **(1) 文字が切れる / (2) スクリーンリーダー用のラベルが無い** の 2 つで、
コントラストとタッチターゲットは**既に満たしているので回帰テストで固定する**のが仕事になる。

## 実装対象の機能

### 1. 一覧の行が文字サイズに追従する

- 経過日数(製品の中心要素)が**どの文字サイズでも省略されない**
- 文字サイズが大きいとき、行を横並びから縦積みに切り替える
- 項目名は最大 2 行まで表示する(任意長の入力なので、それを超える場合のみ省略する)

### 2. スクリーンリーダー対応

- 一覧の行を 1 つのまとまりとして、項目名・最終実施日・経過日数を意味の通る文で読み上げる
- 行内の「やった」ボタンが**どの項目のボタンか**分かるラベルを持つ
- 装飾目的のアイコン(空状態・エラー)を読み上げ対象から外す
- 読み込み中のインジケータにラベルを付ける

### 3. 文字サイズ 200% でも縦に収まる

- 空状態・読み込みエラー・登録・編集の各画面を、縦に入り切らないときスクロールできるようにする

### 4. 非機能要件の回帰テスト

- コントラスト比・タッチターゲット・文字サイズ 200%・読み上げラベル・用語・
  light / dark・片手操作・100 件の遅延生成・クエリ本数を**テストで固定する**

### 5. パフォーマンス計測手順の文書化

- 実機計測(コールドスタート / 初回描画 / 60fps)の再現手順を `docs/` に残す

## 受け入れ条件

### 一覧の行が文字サイズに追従する

- [ ] 文字サイズ 100% / 150% / 200% のいずれでも、**経過日数・最終実施日・ボタンラベルが省略されない**
- [ ] 項目名は 2 行まで表示され、超えた場合のみ省略される
- [ ] 文字サイズ 200% でオーバーフロー例外が出ない
- [ ] 「やった」ボタンの実寸が 100% / 200% のいずれでも 56dp 以上
- [ ] 行タップ(編集への導線)のタップ領域が 48dp 以上

### スクリーンリーダー対応

- [ ] 一覧の各行に、項目名 + 最終実施日 + 経過日数を含む読み上げラベルがある
- [ ] 経過日数の読み上げが数字だけにならない(`42日経過しています` のように読める)
- [ ] 「やった」ボタンのラベルに項目名が含まれる
- [ ] 空状態・読み込みエラーの装飾アイコンが読み上げ対象から外れている
- [ ] 読み込み中のインジケータにラベルがある

### 文字サイズ 200% でも縦に収まる

- [ ] 空状態・読み込みエラー・登録・編集の各画面が、高さ 320dp / 文字サイズ 200% でオーバーフローしない

### 非機能要件の回帰テスト

- [ ] コントラスト比のテストがあり、light / dark の使用ペアすべてで 4.5:1 以上を検証する
- [ ] 文字サイズ 200% のウィジェットテストが一覧・登録・編集の 3 画面にある
- [ ] 用語のテストがあり、**画面に描画された文字列**が `docs/glossary.md`「表記ゆれの禁止一覧」に違反しない
- [ ] dark テーマで 3 画面が破綻しないテストがある
- [ ] 「やった」ボタンと FAB が画面の右半分にあるテストがある(片手操作)
- [ ] 100 件でも構築される `ItemRow` が可視範囲分に収まるテストがある
- [ ] 100 件の一覧表示で発行される SQL が `watchAll` の 1 本だけであることを検証するテストがある

### パフォーマンス計測手順の文書化

- [ ] `docs/development-guidelines.md` に実機計測の再現手順(リリースビルド / 計測項目 / 判定基準)がある

### 全体

- [ ] `dart format` / `flutter analyze --fatal-infos` / `flutter test` が通る
- [ ] CI の 3 ジョブが緑

## 成功指標

- 非機能要件(`docs/product-requirements.md`「非機能要件」)のうち、
  **devcontainer で機械検証できるものが 1 つ残らずテストに落ちている**
- 実機でしか測れない項目は、**手順書と PR ボディで所在が明示されている**(黙って落とさない)

## スコープ外

- 新しい機能の追加、P1 / P2 の前倒し
- アプリアイコン・スプラッシュ・ストア用アセット(リリース準備の別チケット)
- iOS 実機での確認(macOS が必要)
- **Android 実機/エミュレータでの計測**
  — devcontainer に端末・エミュレータ・`adb` がなく、リリースビルドで測れない。
  ユーザー承認のうえ、**テスト内計測 + 手順書**で代替し、実機計測はリリース準備へ送る。
  PR ボディに計測環境と未実施の理由を明記する
- `pubspec.yaml` への依存追加(`integration_test` を含む)
