# 要求: 「やった」の記録と取り消し(Issue #7)

<!-- status: ready -->

## 対象

GitHub Issue [#7](https://github.com/fuji18/lastwhen/issues/7) 「[チケット]「やった」の記録と取り消し」(P0 / フェーズ2 / depends: #5 closed)。

根拠: `docs/product-requirements.md` F3、`docs/functional-design.md`「UC1:「やった」を記録する」「状態ごとの表示」「エラーハンドリング」「テスト戦略」。

## 背景

**このプロダクトの中心操作**。一覧の行は #5 で、登録は #6 で出来ている。`ItemRow` の
「やった」ボタンは既に置かれているが、`onDonePressed` が空実装のまま残っている
(`lib/ui/screens/item_list_screen.dart` の「#7 で繋ぐ」コメント)。ここを塞ぐと
MVP の主要動線(登録 → 記録 → 経過日数を見る)が初めて 1 周する。

## やること

- `ItemListNotifier.markDone` / `undoMarkDone` の追加
- 取り消し用に**直前の `lastDoneAt`** を運ぶ仕組み
- 一覧画面の「やった」ボタンの結線、記録直後のフィードバックと取り消し導線(`SnackBar`)
- 書き込み失敗時の表示(一覧を壊さない)
- 状態管理層のユニットテストとウィジェットテスト

## やらないこと(スコープ外)

- 最終実施日の手動修正(P1 / F16)
- 記録時のメモ・写真(P2)、通知(P1)、履歴の保持(P1 / F12)
- 項目の編集・削除(#8)、相対経過度の表示(#21)
- **データ層の変更**。`markDone` / `restoreLastDoneAt` は #4 で実装・テスト済み
  (`test/data/item_repository_impl_test.dart` に往復・対象なしの両方がある)

## 受け入れ条件(Issue #7 の写し)

- [ ] 一覧の各行に「やった」ボタンがある(#5 で実装済み。結線で満たす)
- [ ] ボタンを押すと、その時点の日時が最終実施日として保存される
- [ ] **確認ダイアログを挟まない**
- [ ] 押した直後にその行の経過日数が `今日` に更新される
- [ ] 押したことが視覚的にフィードバックされる
- [ ] 記録後、**一定時間(4 秒)だけ取り消し導線が表示される**
- [ ] 取り消すと直前の値に戻る。**未実施だった項目は未実施に戻る**
- [ ] 取り消せるのは**直近の 1 件のみ**。別の項目を記録すると前の導線は消える
- [ ] 記録も取り消しも**画面遷移を伴わない**
- [ ] タッチターゲットが 56dp 以上ある(#5 で実装済み・テスト済み)
- [ ] タップから画面反映まで 100ms 以内
- [ ] **保存に失敗した場合、行を更新せず**に失敗が伝わる
- [ ] 時刻は `Clock` 経由で取得している(`DateTime.now()` を直接呼ばない)
- [ ] ウィジェットテストで「確認ダイアログが出ないこと」が検証されている
- [ ] ウィジェットテストで取り消しの往復が検証されている
- [ ] `dart format` / `flutter analyze --fatal-infos` / `flutter test` が通る

## 制約・前提

- **確認ダイアログを出さないのは確定した設計判断**(`CLAUDE.md`「譲らない設計判断」)。
  レビューで蒸し返さない。削除(#8)だけが確認を入れる —— 基準は**元に戻せるか**
- **楽観的 UI 更新を採らない**(`CLAUDE.md`)。保存の完了を待ってから一覧が変わる
- 取り消し導線は Material 3 の `SnackBar` + `SnackBarAction`。独自実装しない
- 追加の UI パッケージを入れない。新規依存を足さない
- 用語は「項目」「記録する / やった」「最終実施日」「経過日数」「未実施」(`docs/glossary.md`)

## ドキュメントとの差分(司令塔が承認済み)

`docs/functional-design.md` は書き込み失敗を `writeErrorProvider`(グローバルな
`StateProvider<String?>`)で運ぶと書いているが、**本チケットでは導入しない**。
理由は `design.md` 判断2。`docs/` 側の追従は `/sync-docs` の担当とし、本チケットでは
`docs/` を書き換えない。
