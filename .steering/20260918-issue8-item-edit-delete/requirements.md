# 要求: 項目の編集と削除(Issue #8)

<!-- status: ready -->

## 対象

GitHub Issue [#8](https://github.com/fuji18/lastwhen/issues/8) 「[チケット] 項目の編集と削除」(P0 / フェーズ2 / depends: #5 closed)。

根拠: `docs/product-requirements.md` F6 / F7(削除の確認と「削除の入口は編集画面だけ」の設計判断を含む)、
`docs/functional-design.md`「画面遷移図」「エラーハンドリング」「テスト戦略」。

## 背景

**これで P0 の機能要件が全部揃う。** 一覧(#5)・登録(#6)・記録と取り消し(#7)は出来ており、
残るのは編集(F6)と削除(F7)だけ。画面遷移図が持つ 3 画面のうち、編集画面だけがまだ無い。

削除は「やった」と逆で**確認を挟む**。基準は**元に戻せるか**で、記録は取り消せるが、
削除は蓄積した記録ごと失われる(`CLAUDE.md`「譲らない設計判断」)。

## やること

- `lib/ui/screens/item_edit_screen.dart`(編集画面。名称変更 + 削除)
- 一覧の行タップから編集画面への導線
- `ItemListNotifier.renameItem` / `deleteItem` と、その結果型
- 削除の確認ダイアログ(Material 3 の `AlertDialog`)
- 状態管理層のユニットテストと編集画面のウィジェットテスト

## やらないこと(スコープ外)

- 最終実施日の手動修正(P1 / F16)
- 削除データの復元・ゴミ箱(`docs/product-requirements.md`「スコープ外」に明記済み)
- 一括削除・複数選択
- **スワイプ削除**(`docs/product-requirements.md` F7 の設計判断で禁止。一覧上の破壊的操作は
  「やった」ボタンと指の動線が重なる)
- **データ層の変更**。`rename` / `delete` は #4 で実装・テスト済み
  (`test/data/item_repository_impl_test.dart` に対象なしのケースもある)
- `docs/` の更新(`/sync-docs` の担当)

## 受け入れ条件(Issue #8 の写し)

### 編集(F6)

- [ ] 一覧の項目をタップすると編集画面に遷移する
- [ ] 項目名を変更して保存できる
- [ ] 保存すると一覧に反映される
- [ ] **最終実施日が編集操作で変化しない**
- [ ] 登録時と同じ検証が働く(空不可・空白のみ不可・トリム・1〜50 文字)
- [ ] キャンセルすると変更が保存されずに一覧へ戻る
- [ ] 保存に失敗した場合、一覧を更新せずに失敗が伝わる

### 削除(F7)

- [ ] 編集画面から項目を削除できる
- [ ] **削除は確認を挟む**
- [ ] 確認をキャンセルすると削除されない
- [ ] 削除した項目が一覧から消える
- [ ] 削除しても他の項目のデータに影響しない
- [ ] 削除後は一覧画面に戻る
- [ ] 削除に失敗した場合、一覧から消さずに失敗が伝わる

### 共通

- [ ] 操作対象が既に存在しない場合、エラーを表示せず一覧を再取得して整合させる
- [ ] `dart format` / `flutter analyze --fatal-infos` / `flutter test` が通る

## 制約・前提

- **「やった」は確認なし、削除は確認あり。** この非対称は意図的
  (`docs/product-requirements.md` F7 の注記)。レビューで一貫性を問われたら、
  基準が「元に戻せるか」であることを示す
- 確認ダイアログは Material 3 の `AlertDialog`。独自実装しない
- 検証ロジックは #3 の `validateItemName` を使い回す。**登録画面と編集画面で書き分けない**
- 「対象なし」はエラーとして表示しない(`docs/functional-design.md`「エラーの分類」)
- **楽観的 UI 更新を採らない**(`CLAUDE.md`)。保存・削除の完了を待ってから画面が変わる
- 追加の UI パッケージを入れない。新規依存を足さない
- 用語は「項目」「記録する / やった」「最終実施日」「経過日数」「未実施」(`docs/glossary.md`)

## ドキュメントとの差分(司令塔が承認済み)

`docs/repository-structure.md`「lib/ui/」のツリーは `theme/` / `screens/` / `widgets/` の
3 つだけを例示しているが、本チケットでは `lib/ui/item_name_error_text.dart` を直下に置く
(理由は `design.md` 判断5)。**`docs/` 側の追従は `/sync-docs` の担当**とし、本チケットでは
`docs/` を書き換えない(#7 の `writeErrorProvider` と同じ扱い)。
