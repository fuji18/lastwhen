# プロジェクト用語集 (Glossary)

## 概要

「最後にいつ」(LastWhen)の開発で使う用語を定義する。**同じものを別の言葉で呼ばない**ことが
目的で、特に「項目」「記録」「経過日数」の 3 語はコード・ドキュメント・UI 文言で表記を揃える。

迷ったらこの文書が正。ここに無い語を新しく使い始めたら、ここに足す。

## ドメイン用語

### 項目(Item)

ユーザーが管理対象として登録した**生活行動 1 件**。「美容院」「歯ブラシ交換」など。

- **コード上の表記**: `Item` / `item`
- **UI 文言**: 「項目」
- **使わない言い換え**: タスク、習慣、アイテム、エントリ、レコード

> **「タスク」と呼ばない理由**: ToDo アプリを連想させ、「完了させるもの」という
> 誤った期待を生む。この製品の項目は完了せず、繰り返される。

### 記録する(Mark Done)

項目に対して「やった」ボタンを押し、その時点の日時を最終実施日として保存する操作。

- **コード上の表記**: `markDone`
- **UI 文言**: ボタンのラベルは「やった」
- **使わない言い換え**: 完了する、チェックする、実行する、達成する

**過去の日付で記録する(F16)**: 記録を忘れた日を後から入れる操作。詳細シートの「日付を指定して記録」から
日付を選ぶ。履歴(`done_logs`)に 1 行**追加**し、最終実施日を置き換えるのではない(#49)。

- **コード上の表記**: `recordPastDate`(状態管理層)/ `addDoneLog`(リポジトリ層)
- **UI 文言**: 「日付を指定して記録」
- **使わない言い換え**: 修正する、変更する(既存の記録は書き換えない)

### 最終実施日(Last Done At)

その項目を最後に記録した日時。**一度も記録がない場合は存在しない**(`null`)。

- **コード上の表記**: `lastDoneAt`(日時を指す)/ `lastDoneDate`(暦日だけを指す)
- **UI 文言**: 「最後にやった日」
- **保存形式**: UTC のエポックミリ秒

### 経過日数(Elapsed Days)

最終実施日から今日までの**暦日の差**。24 時間単位の経過時間ではない。

- **コード上の表記**: `elapsedDays`
- **UI 文言**: 「42日前」「今日」「昨日」「未実施」
- **算出**: 両方の日時をローカル時刻に変換し、その暦日を `DateTime.utc` の点として
  取り直してから差を取る(深夜 0 時への正規化だけでは夏時間で 1 日ずれる)

> **この製品で最も重要な語。** 「経過日数」と「経過時間」を混同すると、
> 朝に記録して翌朝に開いたとき「0日前」と出る不具合になる。

### 未実施(Never Done)

項目は登録されているが、一度も記録されていない状態。`lastDoneAt` が `null`。

- **コード上の表記**: `NeverDone`
- **UI 文言**: 「未実施」
- **使わない言い換え**: 未完了、未着手、0日前

> **「0日前」と表示しない。** 「今日やった」と区別がつかなくなる。

### カテゴリ(Category)【P1】

項目を分けるための区分。項目あたり 0 か 1 つ(多対多にしない)。初期値は 4 つ
(生活 / 健康 / 趣味 / その他)。ユーザーが追加・名前変更・削除できる(F13)。
**カテゴリの無い状態を「未分類」と呼ぶ。**

- **コード上の表記**: `Category` / `CategoryId` / `categoryId`
- **UI 文言**: 「カテゴリ」/ カテゴリの無い状態は「未分類」
- **使わない言い換え**: カテゴリー、タグ、ジャンル

### 目安期間(Interval)【P1】

項目ごとに設定する推奨間隔(日数)。歯ブラシ交換なら 30 日など。MVP には無い。

- **コード上の表記**: `intervalDays`(**単位を名前に含める**)
- **UI 文言**: 「目安の間隔」

### 履歴(Done Log)【P1】

過去に記録したすべての日時。`done_logs` テーブルに 1 回の記録につき 1 行で保存する(#20)。
`items.last_done_at` は最新ログのキャッシュとして残る。

- **コード上の表記**: `DoneLogRow` / `done_logs` テーブル / `Item.recentDoneAts`(直近最大 10 件)

### 前回間隔(Previous Interval)【P1】

直近 2 回の記録の暦日の差。記録が 1 件以下なら無い(`null`)。

- **コード上の表記**: `previousIntervalDays`

### 基準間隔(Baseline Interval)【P1】

実施履歴から学習する、その項目の目安間隔。直近最大 5 間隔の**中央値**(丸めない)。
ユーザーに設定を求めない(F27)。

- **コード上の表記**: `baselineIntervalDays`
- **UI 文言**: 「平均」
- **null のとき画面上は「学習中」**

### 相対経過度(Relative Elapsed)【P1】

経過日数を基準間隔で割った値。基準間隔・経過日数のどちらかが無ければ無い(`null`)。

- **コード上の表記**: `relativeElapsed`

## アプリの技術用語

実装コードに対応物を持つ語。`/sync-docs` の突き合わせ対象。

### Flutter / Dart

iOS と Android を単一コードベースで開発するための UI フレームワークと、その言語。
このプロジェクトのアプリ本体はすべて Dart で書く。

### Drift

Dart 用の型安全な SQLite ラッパー。スキーマ定義からクエリのコードを生成し、
型の誤りをコンパイル時に検出する。マイグレーションの仕組みを標準で持つ。

### Riverpod

状態管理と依存注入のライブラリ。テスト時に `Clock` や `ItemRepository` を
差し替えるためにも使う。

### Material 3

Flutter に同梱される UI コンポーネント群。このプロジェクトでは追加の UI パッケージを
入れず、Material 3 の組み合わせで画面を作る(`docs/ui-design-guidelines.md` §7)。

### Clock

現在時刻を返す抽象インターフェース。`DateTime.now()` を直接呼ぶ代わりにこれを通す。

> **なぜ要るか**: 経過日数の境界条件(日またぎ・うるう年)をテストするには、
> 時刻を自由に設定できる必要がある。

### ドメインレイヤー

ビジネスルールと型だけを置く層。**Flutter・Drift・Riverpod のいずれにも依存しない純 Dart**。
テストが数ミリ秒で回ることがこの制約の見返り。

## 開発ハーネスの用語

開発を進めるための仕組みを指す語。**実装コード(`lib/`)に対応物を持たない**ため、
`/sync-docs` の突き合わせ対象外。ここの語が古くなっても実装は壊れないが、
運用の判断がずれるので、ハーネスを変更したときは合わせて直す。

### 委託禁止領域

Codex に実装を委託しないファイル・ディレクトリ。事故のコストが高い 3 系統
(実行される実体・コンテキストへ注入される実体・全層が読む判定データ)。

このプロジェクトでは汎用項目に加えて `lib/data/database/` と `lib/data/migrations/` が該当する。
全量は `bash .claude/scripts/delegate-codex.sh --print-forbidden` で出る。

### ハーネス

開発を機械的に支える層の総称。hook・CI・git hook・permissions・委託の入口検査。
`.claude/` `.husky/` `.github/workflows/` `.codex/` `.harness/` に分散している。

### 司令塔(メインセッション)

計画・設計判断・統合・ユーザーへの報告を担う Claude のメインセッション。
**実装コードを書かない**(PreToolUse hook がブロックする)。

### ステアリングファイル

作業単位の計画。`.steering/[YYYYMMDD]-[タスク名]/` に
`requirements.md` / `design.md` / `tasklist.md` を置く。履歴としてコミットする。

### フェイルオープン

検査が内部エラーで動かなかったとき、処理を止めずに通す設計。ハーネスの hook は
この方針を採る(層が壊れても開発が止まらない)。ただし**黙って通さず警告を出す**。
**アプリ側はこの方針を採らない**(「失敗を成功に見せない」= フェイルクローズ)。

## アーキテクチャ用語

### レイヤードアーキテクチャ

`ui → state → domain ← data` の 4 層構成。**依存は一方向**で、`domain` は何にも依存しない。

### 依存性逆転

`ItemRepository` の**インターフェースを `domain/` に置き、実装を `data/` に置く**設計。
`state/` は Drift の存在を知らずにテストできる。

### 表示モデル(ItemView)

UI が描画に必要とするものだけを持つ型。`Item`(ドメインモデル)から変換して作る。
`DateTime` の解釈を UI に漏らさないための境界。

### カード(ItemCard)

一覧で 1 項目を表す紙の見た目のコンポーネント。経年ステージに応じて古びる。
**一覧の 1 項目を「行」と呼ばず「カード」と呼ぶ**。

- **コード上の表記**: `ItemCard`

### 詳細シート(ItemDetailSheet)【P1】

カードをタップすると開くボトムシート。最終実施からの経過日数・前回間隔・経年ステージの一言を**最大 3 行**で示し、
編集画面への入口を兼ねる。統計・履歴一覧・基準間隔は出さない。

- **コード上の表記**: `ItemDetailSheet`

### 図鑑(CollectionScreen)【P2】

1 回以上記録した項目のカードをグリッドで並べる画面(F31)。下部ナビでホーム(一覧)と切り替える。
一覧との違いは**載る条件(未実施の項目は載らない)と、カード上に「やった」を持たないこと**。
詳細シートは一覧から開いたときと同じで、「日付を指定して記録」はここからも使える(#49)。

- **コード上の表記**: `CollectionScreen` / `CollectionCard` / `collectionOf`
- **UI 文言**: 「図鑑」/ 下部ナビの一覧側は「ホーム」
- **使わない言い換え**: コレクション、アルバム、ライブラリ

### 楽観的 UI 更新

保存の完了を待たずに先に画面を変える手法。**このプロジェクトでは採らない**
(記録の信頼性が製品価値そのもので、ローカル SQLite なら待っても 100ms 要件を満たせる)。

## ステータス・状態

### 項目の表示状態

| 状態 | 条件 | UI 表示 |
| --- | --- | --- |
| 未実施 | `lastDoneAt == null` | 「未実施」。日付は出さない |
| 今日 | 経過日数 = 0 | 「今日」 |
| 昨日 | 経過日数 = 1 | 「昨日」 |
| N 日前 | 経過日数 >= 2 | 「42日前」 |

### 目安期間に対する状態【P1】

| 状態 | 条件(目安期間を `I` とする) | 表示 |
| --- | --- | --- |
| 余裕あり | 経過日数 < `I` × 0.7 | ラベル + 色 |
| そろそろ | `I` × 0.7 <= 経過日数 < `I` | ラベル + 色 |
| 経過 | 経過日数 >= `I` | ラベル + 色 |

> 閾値は暫定。**色だけで区別しない**(WCAG AA)。

### 経年ステージ(Aging Stage)【P1】

相対経過度に応じた紙の古びの段階。境界は下側を含む。
相対経過度が null のときは真新しい(古びない)。絶対日数で代用しない。

- **コード上の表記**: `AgingStage` / `agingStageOf` / `ItemView.agingStage`

| 相対経過度 | ステージ | コード上の表記 |
| --- | --- | --- |
| 0.5 未満 | 真新しい | `AgingStage.fresh` |
| 0.5 以上 1.0 未満 | 少し経過 | `AgingStage.slightlyAged` |
| 1.0 以上 1.5 未満 | そろそろ | `AgingStage.dueSoon` |
| 1.5 以上 2.0 未満 | 経過 | `AgingStage.aged` |
| 2.0 以上 | かなり経過 | `AgingStage.heavilyAged` |

### チケットの状態(GitHub Issues)

| ラベル | 意味 |
| --- | --- |
| `ticket` | 実装チケット |
| `P0` / `P1` / `P2` | 優先度 |
| `in-progress` | 着手中 |
| `delegate:codex` | Codex への委託が可能と司令塔が判断した |
| `no-changelog` / `no-decision-record` | 記録検査の逃げ道(理由を添えて付ける) |

## データモデル用語

### items テーブル

MVP から存在するテーブル。

| 列 | 型 | 意味 |
| --- | --- | --- |
| `id` | TEXT (PK) | UUID v4 |
| `name` | TEXT NOT NULL | 項目名。トリム後 1〜50 文字 |
| `last_done_at` | INTEGER NULL | 最終実施日時。UTC エポックミリ秒。**NULL = 未実施** |
| `created_at` | INTEGER NOT NULL | 登録日時 |
| `updated_at` | INTEGER NOT NULL | 最終更新日時 |
| `sort_order` | INTEGER NOT NULL | 表示順 |
| `icon` | TEXT NULL | アイコンの保存キー(`ItemIcon.key`)。**NULL = 未選択**(既定アイコンで表示)。v3 で追加(#32) |
| `category_id` | TEXT NULL (FK → categories.id) | カテゴリ。**NULL = 未分類**。カテゴリの削除で NULL に戻る(ON DELETE SET NULL)。v4 で追加(#33) |

### done_logs テーブル

`items` に対する「やった」1 回につき 1 行の履歴。v2 のマイグレーションで追加した(#20)。

| 列 | 型 | 意味 |
| --- | --- | --- |
| `id` | TEXT (PK) | UUID v4 |
| `item_id` | TEXT NOT NULL (FK → items.id) | 対象の項目。項目の削除で行ごと消える(ON DELETE CASCADE) |
| `done_at` | INTEGER NOT NULL | 実施日時。UTC エポックミリ秒(`items.last_done_at` と同じ形式) |

インデックス: `(item_id, done_at)`。

### categories テーブル

項目を分けるカテゴリ。v4 のマイグレーションで追加した(#33)。初期行として 4 件
(生活 / 健康 / 趣味 / その他)を入れる。

| 列 | 型 | 意味 |
| --- | --- | --- |
| `id` | TEXT (PK) | UUID v4 |
| `name` | TEXT NOT NULL | カテゴリ名。トリム後 1〜10 文字・重複不可(検証はドメイン層) |
| `sort_order` | INTEGER NOT NULL | 表示順。`MAX(sort_order) + 1` で採番する |

### ItemId

項目 ID を表す extension type。素の `String` と取り違えないためにある。

### CategoryId

カテゴリ ID を表す extension type。素の `String` と取り違えないためにある。

## エラー・例外

### 入力バリデーションエラー

項目名が空・空白のみ・51 文字以上。**例外にしない**。結果型で返し、
入力欄にとどまったまま理由を表示する。

### 保存失敗

DB への書き込みが失敗した状態。**画面を更新せず**、
「保存できませんでした」と伝える。成功に見せない。

### マイグレーション失敗

スキーマ移行が失敗した状態。**テーブルを作り直さない**。
起動を中断し、データを保持したままエラーを表示する。

### 対象なし

操作対象の項目が既に存在しない(削除と同時操作など)。
エラーとして表示せず、一覧を再取得して整合させる。

## 計算・アルゴリズム

### 経過日数の算出

```
lastDate  = DateTime.utc(ローカル時刻の年, 月, 日)   # 暦日を UTC 上の点として取り直す
todayDate = DateTime.utc(ローカル時刻の年, 月, 日)
elapsed   = max(0, todayDate.difference(lastDate).inDays)
```

**ローカルの `DateTime` 同士で `difference()` を取ってはいけない。** Dart の `difference()` は
実時間差を返すため、夏時間のある地域では 1 日が 23 時間または 25 時間になり、
**深夜 0 時に正規化しても結果が 1 日ずれる**。`DateTime.utc` で取り直せば 1 日が常に
24 時間になり、差分が暦日数と一致する。

負数が出た場合(端末時計の巻き戻し)は `0`(= 今日)として扱う。
**この丸めは `elapsedDays` の内部で行う**(ラベル分類側では行わない)。
