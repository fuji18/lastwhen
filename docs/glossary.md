# プロジェクト用語集 (Glossary)

## 概要

「最後にいつ」(LastWhen)の開発で使う用語を定義する。**同じものを別の言葉で呼ばない**ことが
目的で、特に「項目」「記録」「経過日数」の 3 語はコード・ドキュメント・UI 文言で表記を揃える。

迷ったらこの文書が正。ここに無い語を新しく使い始めたら、ここに足す。

## ドメイン用語

### 項目(Item)

ユーザーが管理対象として登録した**生活行動 1 件**。「美容院」「歯ブラシ交換」など。

- **コード上の表記**: `Item` / `item`
- **UI 文言**: 「項目」
- **使わない言い換え**: タスク、習慣、アイテム、エントリ、レコード

> **「タスク」と呼ばない理由**: ToDo アプリを連想させ、「完了させるもの」という
> 誤った期待を生む。この製品の項目は完了せず、繰り返される。

### 記録する(Mark Done)

項目に対して「やった」ボタンを押し、その時点の日時を最終実施日として保存する操作。

- **コード上の表記**: `markDone`
- **UI 文言**: ボタンのラベルは「やった」
- **使わない言い換え**: 完了する、チェックする、実行する、達成する

### 最終実施日(Last Done At)

その項目を最後に記録した日時。**一度も記録がない場合は存在しない**(`null`)。

- **コード上の表記**: `lastDoneAt`(日時を指す)/ `lastDoneDate`(暦日だけを指す)
- **UI 文言**: 「最後にやった日」
- **保存形式**: UTC のエポックミリ秒

### 経過日数(Elapsed Days)

最終実施日から今日までの**暦日の差**。24 時間単位の経過時間ではない。

- **コード上の表記**: `elapsedDays`
- **UI 文言**: 「42日前」「今日」「昨日」「未実施」
- **算出**: 両方の日時をローカル時刻に変換し、深夜 0 時に正規化してから差を取る

> **この製品で最も重要な語。** 「経過日数」と「経過時間」を混同すると、
> 朝に記録して翌朝に開いたとき「0日前」と出る不具合になる。

### 未実施(Never Done)

項目は登録されているが、一度も記録されていない状態。`lastDoneAt` が `null`。

- **コード上の表記**: `NeverDone`
- **UI 文言**: 「未実施」
- **使わない言い換え**: 未完了、未着手、0日前

> **「0日前」と表示しない。** 「今日やった」と区別がつかなくなる。

### 目安期間(Interval)【P1】

項目ごとに設定する推奨間隔(日数)。歯ブラシ交換なら 30 日など。MVP には無い。

- **コード上の表記**: `intervalDays`(**単位を名前に含める**)
- **UI 文言**: 「目安の間隔」

### 履歴(Done Log)【P1】

過去に記録したすべての日時。MVP は最終実施日のみを持ち、履歴は保持しない。

- **コード上の表記**: `DoneLog` / `done_logs` テーブル

## 技術用語

### Flutter / Dart

iOS と Android を単一コードベースで開発するための UI フレームワークと、その言語。
このプロジェクトのアプリ本体はすべて Dart で書く。

### Drift

Dart 用の型安全な SQLite ラッパー。スキーマ定義からクエリのコードを生成し、
型の誤りをコンパイル時に検出する。マイグレーションの仕組みを標準で持つ。

### Riverpod

状態管理と依存注入のライブラリ。テスト時に `Clock` や `ItemRepository` を
差し替えるためにも使う。

### Material 3

Flutter に同梱される UI コンポーネント群。このプロジェクトでは追加の UI パッケージを
入れず、Material 3 の組み合わせで画面を作る(`docs/ui-design-guidelines.md` §7)。

### Clock

現在時刻を返す抽象インターフェース。`DateTime.now()` を直接呼ぶ代わりにこれを通す。

> **なぜ要るか**: 経過日数の境界条件(日またぎ・うるう年)をテストするには、
> 時刻を自由に設定できる必要がある。

### ドメインレイヤー

ビジネスルールと型だけを置く層。**Flutter・Drift・Riverpod のいずれにも依存しない純 Dart**。
テストが数ミリ秒で回ることがこの制約の見返り。

### 委託禁止領域

Codex に実装を委託しないファイル・ディレクトリ。事故のコストが高い 3 系統
(実行される実体・コンテキストへ注入される実体・全層が読む判定データ)。

このプロジェクトでは汎用項目に加えて `lib/data/database/` と `lib/data/migrations/` が該当する。
全量は `bash .claude/scripts/delegate-codex.sh --print-forbidden` で出る。

### ハーネス

開発を機械的に支える層の総称。hook・CI・git hook・permissions・委託の入口検査。
`.claude/` `.husky/` `.github/workflows/` `.codex/` `.harness/` に分散している。

### 司令塔(メインセッション)

計画・設計判断・統合・ユーザーへの報告を担う Claude のメインセッション。
**実装コードを書かない**(PreToolUse hook がブロックする)。

### ステアリングファイル

作業単位の計画。`.steering/[YYYYMMDD]-[タスク名]/` に
`requirements.md` / `design.md` / `tasklist.md` を置く。履歴としてコミットする。

| 略語 | 正式名称 | 意味 |
| --- | --- | --- |
| MVP | Minimum Viable Product | 最小限の価値を届ける最初のリリース。ここでは P0 機能(F1〜F8) |
| PRD | Product Requirements Document | プロダクト要求定義書(`docs/product-requirements.md`) |
| P0 / P1 / P2 | Priority 0 / 1 / 2 | 優先度。**P0 以外は実装しない**(スコープガード) |
| KPI | Key Performance Indicator | 重要業績評価指標 |
| WCAG AA | Web Content Accessibility Guidelines Level AA | アクセシビリティ基準。コントラスト比 4.5:1 など |

| UTC | Coordinated Universal Time | 協定世界時。日時の保存形式 |
| ORM | Object-Relational Mapping | DB の行とオブジェクトを対応づける仕組み。ここでは Drift |
| CRUD | Create / Read / Update / Delete | データ操作の 4 基本 |
| CI | Continuous Integration | GitHub Actions の自動検証 |

## アーキテクチャ用語

### レイヤードアーキテクチャ

`ui → state → domain ← data` の 4 層構成。**依存は一方向**で、`domain` は何にも依存しない。

### 依存性逆転

`ItemRepository` の**インターフェースを `domain/` に置き、実装を `data/` に置く**設計。
`state/` は Drift の存在を知らずにテストできる。

### 表示モデル(ItemView)

UI が描画に必要とするものだけを持つ型。`Item`(ドメインモデル)から変換して作る。
`DateTime` の解釈を UI に漏らさないための境界。

### 楽観的 UI 更新

保存の完了を待たずに先に画面を変える手法。**このプロジェクトでは採らない**
(記録の信頼性が製品価値そのもので、ローカル SQLite なら待っても 100ms 要件を満たせる)。

### フェイルオープン

検査が内部エラーで動かなかったとき、処理を止めずに通す設計。ハーネスの hook は
この方針を採る(層が壊れても開発が止まらない)。ただし**黙って通さず警告を出す**。

## ステータス・状態

### 項目の表示状態

| 状態 | 条件 | UI 表示 |
| --- | --- | --- |
| 未実施 | `lastDoneAt == null` | 「未実施」。日付は出さない |
| 今日 | 経過日数 = 0 | 「今日」 |
| 昨日 | 経過日数 = 1 | 「昨日」 |
| N 日前 | 経過日数 >= 2 | 「42日前」 |

### 目安期間に対する状態【P1】

| 状態 | 条件(目安期間を `I` とする) | 表示 |
| --- | --- | --- |
| 余裕あり | 経過日数 < `I` × 0.7 | ラベル + 色 |
| そろそろ | `I` × 0.7 <= 経過日数 < `I` | ラベル + 色 |
| 経過 | 経過日数 >= `I` | ラベル + 色 |

> 閾値は暫定。**色だけで区別しない**(WCAG AA)。

### チケットの状態(GitHub Issues)

| ラベル | 意味 |
| --- | --- |
| `ticket` | 実装チケット |
| `P0` / `P1` / `P2` | 優先度 |
| `in-progress` | 着手中 |
| `delegate:codex` | Codex への委託が可能と司令塔が判断した |
| `no-changelog` / `no-decision-record` | 記録検査の逃げ道(理由を添えて付ける) |

## データモデル用語

### items テーブル

MVP で唯一のテーブル。

| 列 | 型 | 意味 |
| --- | --- | --- |
| `id` | TEXT (PK) | UUID v4 |
| `name` | TEXT NOT NULL | 項目名。トリム後 1〜50 文字 |
| `last_done_at` | INTEGER NULL | 最終実施日時。UTC エポックミリ秒。**NULL = 未実施** |
| `created_at` | INTEGER NOT NULL | 登録日時 |
| `updated_at` | INTEGER NOT NULL | 最終更新日時 |
| `sort_order` | INTEGER NOT NULL | 表示順 |

### ItemId

項目 ID を表す extension type。素の `String` と取り違えないためにある。

## エラー・例外

### 入力バリデーションエラー

項目名が空・空白のみ・51 文字以上。**例外にしない**。結果型で返し、
入力欄にとどまったまま理由を表示する。

### 保存失敗

DB への書き込みが失敗した状態。**画面を更新せず**、
「保存できませんでした」と伝える。成功に見せない。

### マイグレーション失敗

スキーマ移行が失敗した状態。**テーブルを作り直さない**。
起動を中断し、データを保持したままエラーを表示する。

### 対象なし

操作対象の項目が既に存在しない(削除と同時操作など)。
エラーとして表示せず、一覧を再取得して整合させる。

## 計算・アルゴリズム

### 経過日数の算出

```
lastDate  = 正規化(lastDoneAt.toLocal())   # 深夜 0 時に切り下げ
todayDate = 正規化(now.toLocal())
elapsed   = todayDate.difference(lastDate).inDays
```

**正規化を省略して `inDays` を取ってはいけない。** 夏時間のある地域では
1 日が 23 時間または 25 時間になり、結果が 1 日ずれる。

負数が出た場合(端末時計の巻き戻し)は `0`(= 今日)として扱う。

## 表記ゆれの禁止一覧

| 使う | 使わない |
| --- | --- |
| 項目 | タスク、習慣、アイテム、エントリ |
| 記録する / やった | 完了する、チェックする、達成する |
| 最終実施日 | 最終更新日、前回日、実施日 |
| 経過日数 | 経過時間、日数差、インターバル |
| 未実施 | 未完了、未着手、0日前 |
| 目安期間 | 推奨間隔、サイクル、周期 |
